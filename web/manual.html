Overview

Checkpoint is a puzzle game about one honest idea: a quantum computer makes mistakes, and you can catch many of them by adding checks. Checks do not repair anything. They let you throw away the runs that went wrong, so the results you keep are more often right.

Every score in the game is computed with Qiskit from the puzzle's own noise model. No number on a results screen is set by hand.

Note: Notes like this one appear in this manual to point out things that need special attention, and to refer to other sections that say more about a topic.

1. Detection, not correction

There are three ways to deal with errors on a quantum computer. Checkpoint is about the first one only.

1-1. Detection

Checks flag the errors they can see, and those runs are discarded. Nothing is repaired. This is the game.

1-2. Mitigation

The noisy results are kept, and the estimate is corrected afterwards, in post-processing.

1-3. Correction

Qubits are encoded into larger codes, checked over and over, and errors are undone while the computation runs.

The goal

1. What you are trying to do

Each puzzle is a small quantum circuit. Run it many times and measure the qubits, and every run should give a correct result. But every gate has a small chance of an error, and errors change some results. Those runs are wrong.

You add checks. A check watches part of the circuit for certain errors. When it sees one, it flags the run, and the run is discarded. A check never fixes a run; it only decides whether to keep it.

2. The three numbers

Every layout of checks is judged on three numbers.

2-1. Fidelity

Question: Of the runs you kept, how close are they to the correct results?

Better: Higher.

2-2. Yield

Question: What fraction of all runs did you keep?

Better: Higher.

2-3. Cost

Question: How much extra hardware did the checks add? Cost counts ancilla qubits plus extra two-qubit gates.

Better: Lower.

These pull against each other. A check raises Fidelity by discarding bad runs, but it also discards some good ones, and its own gates can add errors. Each puzzle sets a target for Fidelity and a target for Yield. Meet both to solve it. Among layouts that do, a lower Cost is neater.

Note: Puzzle 00 shows the whole idea in one picture. Its OUTPUTS screen lists every possible result, how often it appears with no checks, and how often among the runs you kept.

O marks a correct result, X a wrong one. The check removed most wrong results, but 11 (both qubits flipped) slipped through.

The board

1. Reading the board

1-1. Wires

Looks like: one thick black line per qubit (q0, q1, ...). Description: Time runs left to right. The light pulses are decoration.

1-2. Slots

Looks like: the numbered gaps between gate columns. Description: Checks start and end on slots. Some puzzles only allow certain slots; the others are drawn in red.

1-3. Gates

Looks like: beige tiles. Description: H, S and S† act on one qubit. A CNOT is a small black square (the control) joined to a + (the target). T and T† are the violet tiles; they limit which checks may pass (see How a check works).

1-4. Error badges

Looks like: a percentage next to a gate. Description: The gate's chance of an error in this puzzle's noise model. An orange badge is a hot gate, much noisier than the rest. Once you place checks, the badge also shows SEEN: how much of that gate's possible errors your checks would flag.

1-5. Readout

Looks like: the M tiles on the right. Description: Each qubit is measured here. The percentage is the chance of reading it wrong.

1-6. Placed checks

Looks like: a row of its own under the circuit. Description: The check starts in |+⟩, runs as a coloured pipe (teal for Z, blue for X, yellow for Y) and ends at Mx. It turns red if VERIFY finds a problem with it.

2. What a correct result looks like

Press i. Under CORRECT RESULT the game lists what every noiseless result has in common, computed from the circuit itself:

Always 000Only one result is correct. q0 = q1q0 and q1 always read the same (both 0 or both 1). q0 ≠ q1They always differ. q1 = 0q1 always reads 0. q2 is randomAny value is fine; there is nothing to check on q2.

These rules are the key to most puzzles. A good check usually tests one rule.!! If noise breaks the rule, the check flags the run.

How a check works

1. Start, span and end

You drop a check piece on a slot: that is its start edge. You drag its handle to a later slot: that is its end edge. The part between is its span. Drop a second piece on the same slot to start one check on two qubits; several puzzles need this.

2. The Pauli changes as it moves

A check carries a Pauli (X, Y or Z) through every gate in its span, and each gate can change it. The game works this out for you and draws it as small chips at every slot inside the span (the trail).

HSwaps X and Z. STurns X into Y (Z stays Z). CNOTCopies an X from the control onto the target, and a Z from the target onto the control. T, T†Only Z (or nothing) may pass on that qubit. An X or Y there is blocked.

Note: The last line is the T-gate rule. T commutes with Z, but it turns an X or a Y into something that is not a single Pauli, so the check could no longer end in a clean edge. The game refuses such a span and rings the T gate that blocks it in red.

3. What a check catches

The wires a check watches glow in its colour. An error is flagged when it happens on a glowing wire and does not commute with the check's Pauli there.<-- the whole game, really

CHECK'S PAULI THERECATCHESIN WORDS

Errors outside the glow go unseen. Click a placed check to open its panel: it lists the edges and tags each stretch of glowing wire with what it SEES.

4. Ending at the readout

If a check ends at the last slot and its end edge has only Z's, it can use the final readout: instead of extra gates, its answer is read from the qubits' own measurements. That is cheaper, its helper qubit never has to wait, and it also catches a wrong reading on those qubits. Two wrong readings at once cancel out, though. The switch is in the check's panel.

5. Checks are not free

Every check adds a helper qubit and gates, and those can have errors too. A check that ends with gates keeps its helper qubit waiting across the span, and waiting is noisy. A check that watches nothing useful can make things worse.

Note: Two checks that overlap can clash: together they flag runs that had no error at all. VERIFY finds such pairs and draws them in red. A single check on its own never clashes.

Playing a puzzle

1. Step by step

  1. Read i: the correct-result rules, how many checks you have, and the targets.
  2. Drag a check piece from the rack onto a slot on a qubit. Drop more pieces on the same slot to widen it.
  3. Drag the handle to a later slot. If the span is not allowed (for example X crossing a T gate), a notice explains why; press WHY? in it for the full reason.
  4. Look at the trail, the glow and the SEEN badges. Drag the end of a placed check to try other spans.
  5. Press VERIFY. It runs the circuit with no noise: your checks must not change the correct result or flag a clean run. Two checks that clash are shown in red.
  6. Press TEST UNDER NOISE to score the layout.

Notices appear at the bottom right and close on their own; problems stay until you close them or change the board.

2. Keyboard shortcuts

The puzzle screen has the following keyboard shortcuts:

Z, X, Y: Pick a check type (only the types the puzzle offers)

E: Pick the remove tool

Esc: Cancel an unfinished check, or close a window

You can also click a check type and then click two slots instead of dragging.

3. The solution

The red ! button (and SOLUTION on the results screen) shows a worked solution: the circuit with its checks, its real scores, and why it works. You must hold HOLD YES for a few seconds first. LOAD ONTO BOARD puts it on your board so you can test it yourself.only if stuck!

It is worth a look even after you solve a puzzle, to compare approaches.

Reading the results

1-1. Histograms

Each bar counts the layouts the game evaluated for this puzzle. The dashed line is the target; red bars miss it, green bars meet it. ▼ is this run, ★ your best result among runs that met every target, ◆ the automated reference.

1-2. Fidelity against Yield

Every evaluated layout is a dot: up is better Fidelity, right keeps more runs. The bright line joins the best trade-offs found. YOU is this run; faint rings are your earlier runs.

1-3. Comparison

F, Y, ancillas, extra two-qubit gates and extra depth for no checks, the automated reference and you. The automated reference is the layout chosen by qiskit-paulice with the same budget; it optimises its own measure, not this game's score.

1-4. Printouts

RUN REPORT, LESSON, and after the last T-count puzzle a T-COUNT STUDY table.

Note: Every score is calculated with Qiskit Aer from the puzzle's stated noise model, without sampling noise, so the same layout always gets the same score.

The evaluated layouts are a large search, not every possible layout: "best found" is not a proof that nothing better exists.

Strategy tips

  1. Start from the rules. Read the correct-result rules and build one check for each. A check that ends at the readout as Z on q1 tests "q1 = 0"; one that ends as Z on q0 and q3 tests "q0 = q3".
  2. Cover the noisy gates. Orange badges first. Watch SEEN rise as you place checks.
  3. Match the Pauli to the noise. If most errors are phase flips, you need checks that are X where it matters. If they are bit flips, Z.
  4. End at the readout when you can. It costs less and the helper qubit does not wait.
  5. Watch Yield. Every check discards some good runs too. Stop adding checks when the next one barely helps.
  6. Plan around T gates. The check must be Z or nothing on the T qubit when it passes.
  7. Try two-qubit starts. One check started on two qubits can end up testing a rule that no single-qubit start reaches.
  8. Compare. Use the bright line and the faint rings to see whether a different layout trades better.

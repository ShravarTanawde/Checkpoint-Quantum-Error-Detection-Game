## 00 Why Check?

**Brief.** This circuit copies q0 onto q1. q0 starts at 0, so the correct result is always 00. The CNOT is noisy, so some runs come out wrong.

**Learning moment.** Without checks, noise turns some results into 01, 10 or 11. A check cannot fix those runs, but it can notice many of them and discard them. What is left is more often correct: that is Fidelity. You also keep fewer runs: that is Yield. This check asks whether q0 and q1 are still equal, so it catches a flip on one qubit; two flips at once (11) can still slip through.

## 02 Which Errors Can You See?

**Brief.** This circuit is dominated by phase-flip errors, represented by Z. You now have X and Z checks. Try each type and compare what happens to Fidelity and Yield. Check edges must sit between slots 1 and 4.

**Learning moment.** A Z check commutes with a Z error, so that error does not flip the check's result. An X check anticommutes with Z, so a phase flip can make the check flag the run. The check type matters because it determines which errors are visible to the check at that point in the circuit. This is not a guarantee that X is always best: it is useful here because this puzzle's noise model is dominated by Z errors.

## 03 How Long Should a Check Be?

**Brief.** Two CNOTs create a three-qubit GHZ state, followed by a long stretch of low-error gates. You have one check. Cover the errors worth catching without letting the check wait longer than it needs to. House rule: every check must end by slot 8, so none can use the final readout.

**Learning moment.** A check's ancilla must stay coherent across the whole span between its start and end edges. While it waits, it can pick up idle noise of its own. In this puzzle, extending a check far beyond the two noisy CNOTs adds little useful detection, but gives the ancilla more time to suffer an error. That can cause clean runs to be rejected: Yield falls while Fidelity changes very little. A short check can be better than a long one.

**Noise.** level noise with heavy idling (p2 0.02, p1 0.0005, idle 0.02, readout 0.005). Slots limited to {'min': 1, 'max': 8}.

## 06 Follow the Pauli

**Brief.** You can start only Z checks. Place one before different gates and watch how the game calculates its end edge. The end edge is determined by the gates inside the check's span.

**Learning moment.** The check's start and end edges must describe the same measurement carried through the intervening gates. The game calculates this transformation for you. For example, H swaps X and Z; S maps X to Y (and maps Y to −X); CNOT can spread an X from its control to its target and a Z from its target back to its control. The mathematical rule is U P U†, but you can learn the behavior by watching the edge change. If a check ends at the final readout and its end edge contains only Z and identity, it may be merged into the measured parity without extra end-edge gates.

**Noise.** uniform level noise (p2 0.02, p1 0.001, idle 0.002, readout 0.005).

**Parts.** Z; left edge up to 2 qubits; 1 ancilla(s). T count 0.

**Example winning layout.** `[{'left': 0, 'right': 6, 'paulis': {'0': 'Z'}}]` gives fidelity 0.9942 at yield 0.9511, cost 2.

## 07 The Readout Blind Spot

**Brief.** The gates are relatively reliable, but the final measurements are noisy. Compare a gate-based check with a check that uses the final readout to calculate its syndrome.

**Learning moment.** A gate-based check finishes before the data qubits are measured. It therefore cannot flag an error that happens only during the final readout. When a check's end edge contains only Z and identity and reaches the final slot, it can be merged into the readout: measured data bits contribute to the syndrome parity. This can make a single readout flip visible to the check without adding end-edge gates. But parity has a blind spot, too: two flips can cancel each other. Compare the Fidelity and Yield of the same check with final readout on and off.

## 08 The T-Gate Rule

**Brief.** This mirror circuit applies T and later undoes it with T†, so the ideal output is 000. Try to span the T gate with different Pauli checks and see which paths are allowed.

**Learning moment.** H, S, and CNOT are Clifford gates: they transform a Pauli into another Pauli, so the game can calculate a matching end edge. T is different. Z commutes with T and remains Z, but X or Y on that qubit generally becomes a combination of Paulis rather than one Pauli. This game's check must stay a single Pauli, so it allows a check to cross T or T† only when the propagated operator on that qubit is I or Z. This is a restriction on the check path, not a claim that the circuit itself cannot use T gates.

**Noise.** uniform level noise (p2 0.02, p1 0.0005, idle 0.002, readout 0.005).

**Parts.** Z, X; left edge up to 2 qubits; 1 ancilla(s). T count 2.

**Example winning layout.** `[{'left': 2, 'right': 8, 'paulis': {'0': 'X', '2': 'Z'}}]` gives fidelity 0.9531 at yield 0.9244, cost 3.
